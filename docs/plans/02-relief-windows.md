# 計画 02: 緩和の場面（人影が一度消えて、また現れる）

## 目的
ホラーは「緊張 → 緩和 → より強い緊張」の繰り返しで効く（調査: docs/godot-tips.md の 2）。
人影が濃くなる途中で、数秒だけ消える場面を入れる。消えて安心したところに、前より近づいて戻ってくる。

## 仕様
ステージ設定（stages/*.json）に、任意の項目 `relief` を足す。例: `"relief": [[41, 45], [66, 70]]`（[開始秒, 終了秒] の配列）。無ければ従来どおり。

0. **先に直す不具合（警告が通るかの判定のぶれ）**: 今の `_on_warn` / `_on_comment` は、「人影が映っているか」を `ghost_layer.modulate.a`（ちらつきで 0.7〜1.0 倍に揺れる、見た目の濃さ）で判定している。映り始めの境目で、同じ操作が通ったり通らなかったりする（MiniMax の報告で発覚）。
   - 判定は **`_ghost_alpha_at(t)`（時間割どおりの濃さ。ちらつきなし）** を使う。対象は、`seen` の判定（`SEEN_THRESHOLD` との比較）と、`_on_warn` の信頼のスコア計算（`ghost_layer.modulate.a * 0.8` の部分）の両方
   - 見た目（`ghost_layer.modulate.a` の更新、表情・音の連動）は今のまま変えない
   - この変更のあとも、既存のテスト 76 件 + test_playthrough.gd の 20 件が、そのまま成功すること（成功しないテストがあれば、判定のぶれに依存していたはずなので、テストを時間割どおりの濃さに合わせて直してよい。直した箇所は報告に書く）

1. **人影の濃さ**
   - 今の `_ghost_alpha_at(time)` は「時間割の曲線から濃さを返す」関数。これを `_curve_alpha(time)`（今のまま・名前だけ変更）と、`_relief_factor(time)`（緩和の係数）に分ける
   - `_relief_factor(time)`: 緩和の時間帯の中は 0。時間帯の前後 0.8 秒で、1 ↔ 0 を直線でなめらかに変える（時間帯の外は 1）。複数の時間帯に対応する
   - 新しい `_ghost_alpha_at(time)` = `_curve_alpha(time) * _relief_factor(time)`。**呼び出し側は従来どおり `_ghost_alpha_at` を使う**（表情の判定・人影の表示・音の連動が、自動で緩和に追従する）
2. **近づく演出は、緩和に影響されない**: 人影の大きさ（`ghost_scale` の補間、`_process` 内の `approach`）は `_curve_alpha` を使う。消えて、戻ってきたとき、前より大きくなっている
3. **`_first_seen_time()`（失敗時の「人影が映り始めた時刻」）は `_curve_alpha` を使う**（緩和は含めない）
4. **戻ってくる瞬間の音**: 緩和の時間帯が終わった瞬間に、効果音 `creak`（既存。`_play("creak")`）を 1 回鳴らす。時間帯ごとに 1 回だけ。進行を覚える変数（例: `relief_idx`）を使う
5. **緩和中の警告は罰しない**: `_on_warn` と `_on_comment` で、`_relief_factor(t) < 1.0` かつ `_curve_alpha(t) >= SEEN_THRESHOLD`（緩和がなければ映っているはずの時間）なら、誤警告にしない。代わりに `hint_label.text = "人影が消えた…。また現れるはず。"`、`lock_left = 1.0`、`_say` はしない、`return`。配信の `_on_comment` では、先に書き込む `_say("あなた", ...)` と `_play("send")` はそのままでよい
   - `_on_warn` は `has_mark` が false の判定より後、`_say("あなた", ...)` の前に入れる。ただし `_play("send")` と `_say("あなた", ...)` は鳴らす・出すままでもよい（どちらでもよいが、誤警告の処理（`false_alarms += 1` など）には進まないこと）
6. **ステージ設定**
   - stage1: `relief` なし（練習のまま）
   - stage2: `"relief": [[41, 45], [66, 70]]`。あわせて timeline に、緩和の開始直後の台詞を足す: `[42, "...あれ、気のせいかな。"]`（既存の `[42, ...]` と重なる場合は 42.5 など近い時刻にずらして時刻順を保つ）、`[67, "ふう...なんか、ほっとした。"]`
   - stage3: `"relief": [[50, 54], [72, 75]]`。timeline に `[51, "あれ？ 今、何か映ってなかった？"]` と `[73, "...気のせいだよね、うん。"]` を足す（時刻順を保つ）。stage3 は配信なので `fail_at` は 100
7. **難易度レポート**（`balance_report.py`）: ステージごとに、緩和の時間帯を `緩和: 41〜45秒 / 66〜70秒`（無ければ `緩和: なし`）と表示する行を足す。ほかの出力は変えない

## テスト（tests/test_logic.gd の末尾の `quit(...)` の直前に足す。既存のテストは変更しない）
- `_relief_factor`: stage2 で、緩和の外（例: 30 秒）は 1.0、時間帯の真ん中（43 秒）は 0.0、境目の 0.4 秒手前（40.6 秒）は 0〜1 の間
- `_ghost_alpha_at(43.0)` は 0（`_curve_alpha(43.0)` は 0 より大きい）
- `_first_seen_time()` は `relief` の有無に影響されない（stage2 の値が、`_curve_alpha` で求めた値と一致）
- 緩和中の警告: stage2 で `_start_call()`、`at(m, 43.0)` のあと `_set_mark(m.ghost_box.get_center())` → `_on_warn(1)` → `m.false_alarms == 0`、`m.state == m.State.PLAYING`、`m.lock_left > 0`
- 緩和が無いステージ（stage1）では、`_relief_factor(30.0) == 1.0`
- 戻る瞬間の音: stage2 で `at(m, 46.0)` のあと `m.relief_idx >= 1`（`relief_idx` はあなたが付けた変数名に合わせてよい）
- 配信（stage3）の緩和中のコメント: `at(m, 52.0)` のあと `_on_comment(0)` → `m.false_alarms == 0`
