# 素材の作り方の検証（2026-10-05 更新）

## 結論

**実写風の画像は、SDXL（RealVisXL V5.0）で作れる。** 人物・部屋・「背後の異変」まで実写として成立し、怖さも出る。
3D 箱人形案（第1弾）は却下。ウェブカメラ風シェーダー（`webcam.gdshader`）は画像に重ねて流用する。

## 環境の事実（重要）

- GPU: RTX 4060（8GB）。1枚（1024x576・28ステップ）が約10秒
- A1111 WebUI（`C:\sd\stable-diffusion-webui`）の venv は **PyTorch が CPU 版**（2.12.1+cpu）で、SDXL の読み込みが `Torch not compiled with CUDA enabled` で失敗する。過去のスプライト生成が CPU だった可能性が高い（推測）
- 対策: **専用の CUDA 版環境 `C:\sd\venv-cuda`** を新設（torch 2.11.0+cu128、diffusers 0.40.0）。A1111 の venv は無変更
- モデルは共用: 標準 SDXL = `C:\sd\stable-diffusion-webui\models\Stable-diffusion\sd_xl_base_1.0.safetensors`、実写特化 = `C:\sd\models-extra\RealVisXL_V5.0_fp16.safetensors`（Hugging Face `SG161222/RealVisXL_V5.0`、約6.9GB。**ライセンス・商用可否は配布前に要確認**）
- 生成スクリプト: `sd_test.py`（`rooms` / `persons` / `scenes` / `ghost`）。実行: `C:\sd\venv-cuda\Scripts\python.exe sd_test.py scenes 6`

## 検証の経過と学び

| 回 | 内容 | 結果 |
|---|---|---|
| 1 | 標準 SDXL・プロンプトに「webcam screenshot, video call」 | 部屋は 1/4 だけ良好。他は画面の入れ子やイラスト調 |
| 2 | プロンプトを「cheap laptop webcam で撮った写真」に変更 | 部屋 6/6 が実写風。人物のアップも 3/4 が実写 |
| 3 | 標準 SDXL で「人物＋机＋ドア」の構図 | **ほぼイラスト調**。構図を足すと実写から外れる（`outputs/sd/round2_base/`） |
| 4 | **RealVisXL** で同じ構図 | **6/6 が実写**。暗さ・不穏さも出た（`outputs/sd/sheet_scenes.png`） |
| 5 | scene_1 のドアにインペイントで人影 | **成功**。背後に長い黒髪の人物が立ち、顔が半分覗く（`outputs/sd/base_ghost.png`） |

学び:
- 「video call」「screenshot」という語は画面の入れ子を招く。使わない
- 標準 SDXL は日本人女性＋構図でアニメ調に流れる。**実写は RealVisXL を使う**
- 異変は **インペイント（範囲指定の描き足し）** で作る。同じ元画像から段階違いを作れば、人物と背景が揃う

## 異変の段階（縦の1本で使う）

- 段階0: 何も映らない（`base.png`）
- 段階1: ほとんど見えない淡い影（`base_ghost_faint.png`。強さ 0.6 で試作）
- 段階2: はっきり映る（`base_ghost.png`）

## 未解決・次の課題

- 人物の「反応」画像（振り返る・立ち上がる・倒れる）を、顔や服の見た目をそろえて作る方法。候補: img2img を低強度で重ねる、IP-Adapter、ControlNet（A1111 側は mediapipe のエラーで未使用）。**最大の技術課題**
- 画像だけでは「動画」にならない。候補: 微小な拡大縮小・揺れ・ノイズで静止画を生きた映像に見せる（シェーダー）。AI 動画生成（AnimateDiff 等）は 8GB では負荷が重い見込みで、後回し
- 音は未検証（環境音・足音・通話ノイズ）
- 生成画像の権利・利用規約の確認（RealVisXL、SDXL 標準）

## 追記（2026-10-05 午前）: 表情差分と2つ目の通話の検証

- **表情差分は作れる**: 上半身だけを範囲指定して描き直す（`sd_test.py react`）。プロンプトに人物の特徴（「日本人・東アジア系・黒髪・灰色パーカー」）を明記すると、同一人物に近い顔が保てた。指定しないと別人（欧米風）になった。完全な同一人物ではない（前髪などが少し変わる）。ドアのほうへ向く動きは出せず、正面向きのまま
- 男性（2つ目の通話用、`outputs/sd/base2.png`）でも同様に成功。表情は不安・怯え・驚愕。口を押さえる動きは出ず、驚きの表情として読める
- **窓の外の人影は失敗（3回9枚）**: 背景が真っ暗な窓だと、描き足しても「暗闇」に塗られる。成功した1つ目の通話は、背後に少し明るい開口部（ドアと廊下）があった。人影を足すには、背景にわずかな明るさ・輪郭が要る
- 次の方針: 2つ目の通話は「背後にドアのある部屋＋男性」を実証済みの手法で作り直す。異変の種類を変えるのは、その次（候補: 鏡、廊下の奥、画面端の一瞬の映り込み）
- Qwen（qwen3:8b）はセリフ案の下書きには使えるが、話のつながらない案が多く、手直しが要る。qwen2.5-coder:7b による GDScript のレビューは誤指摘ばかりで役に立たなかった（実際の画面・テストで反証済み）
